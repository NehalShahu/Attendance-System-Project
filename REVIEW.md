# REVIEW.md

List every defect found in the starter `app/main.py`. For each defect: location, what is wrong, a concrete failing input, and the fix.

| # | Where | What is wrong | Concrete failing input / symptom | Fix |
|---|---|---|---|---|
| 1 | `MongoClient(...)` (line 22) | No `tz_aware=True`; PyMongo returns naive datetimes. Any datetime arithmetic with aware objects raises `TypeError`. | First endpoint call that subtracts two datetimes → `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Added `tz_aware=True` to MongoClient. |
| 2 | `compute_late_minutes` (lines 33-37) | Three bugs: (a) `int(minutes) > 10` uses float division so 09:40:01 IST = 601 s gives `int(10.016) = 10` which is NOT `> 10` → returns 0 instead of 10. Grace period must be strictly > 600 s, compared in seconds. (b) Uses the punch's own tzinfo instead of converting to IST. (c) Ignores overnight shifts; does not truncate to seconds (R1). | shift 09:30, punch_in 09:40:01 IST → expected `late_minutes=10`, actual `0`. | Rewrote: convert punch to IST, truncate to seconds, compute `diff_s = int((pi_ist - shift_dt).total_seconds())`, return 0 if `diff_s <= 600`, else `diff_s // 60`. |
| 3 | `compute_work_hours` (line 41) | `round()` uses banker's rounding (round-half-to-even), but R4 requires half-up. Also `.total_seconds()` returns a float with sub-second noise if the datetimes have microseconds; no sub-second truncation. | punch_in=09:30:00, punch_out=14:30:30 → 18030 s. `round(18030/3600, 2)` = `round(5.008333..., 2)` = 5.01. Half-up gives same here, but at exact mid-points banker's and half-up diverge. | Use `Decimal(int(seconds)) / Decimal(3600)`, quantise with `ROUND_HALF_UP`. Truncate both datetimes to seconds first with `_truncate_to_second`. |
| 4 | `compute_overtime` (lines 44-47) | (a) No 30-minute minimum (R3). (b) `datetime.fromisoformat(date_str).replace(..., tzinfo=IST)` stamps, not converts — wrong for any non-midnight local time. (c) Overnight shifts: shift_end falls on the next calendar day, but the code always uses `date_str`'s date. (d) Mixes aware/naive datetimes. | Overnight shift (22:00-06:00), punch_out 06:01 IST: overtime should be 0 (1 min < 30 min threshold), but `0 < 30` check is missing so actual = 1. | Detect overnight from `shift_end_min <= shift_start_min`, advance date by 1 day when overnight, build aware IST shift_end, compare integer seconds, return 0 if `diff_s < 1800`. |
| 5 | `POST /employees` (lines 79-85) | (a) TOCTOU race: `find_one` then `insert_one` — two concurrent creates both pass the check and create duplicates. (b) `datetime.now()` returns a naive local-time datetime. (c) `created_at` is returned as a Python datetime object, not epoch ms. (d) No validation of `emp_code` pattern, shift equality, or date format. | Two concurrent `POST /employees` with same `emp_code` → both return 201; database has two documents. Or: response `created_at` is an ISO string, not an integer. | Added unique index on `emp_code`; replaced check-then-insert with `try insert_one / except DuplicateKeyError → 409`; used `datetime.now(tz=timezone.utc)`; serialised through `to_api_employee`; added Pydantic validators for all fields. |
| 6 | `GET /employees` (lines 89-96) | (a) `skip = page * page_size` — page 1 skips 20 rows (off by one; should be `(page-1)*page_size`). (b) `total` calls `count_documents({})`, ignoring the department filter. (c) No sort by `emp_code`. (d) `page_size` not bounded to 100. | `GET /employees?page=1` returns rows 21-40. `GET /employees?department=Sales` shows total = all employees. | Changed to `(page - 1) * page_size`; moved `count_documents(q)` after building `q`; added `.sort("emp_code", ASCENDING)`; added `Query(ge=1, le=100)`. |
| 7 | `punch_in` (lines 101-121) — unknown employee | `emp = db.employees.find_one(...)` may return `None`; the next line `emp["shift_start"]` crashes with `TypeError: 'NoneType' object is not subscriptable` → 500 instead of 404. | `POST /attendance/punch-in {"emp_code": "NONEXISTENT"}` → HTTP 500. | Added `if emp is None: raise HTTPException(404, "Employee not found")` immediately after the lookup. |
| 8 | `punch_in` (line 102) — timezone and punched_at handling | `datetime.fromtimestamp(body.punched_at / 1000)` uses the **server's local timezone**, not UTC. `if body.punched_at` treats `punched_at=0` as missing. No range validation — seconds-looking values (< 1e11) and floats are silently accepted. | `punched_at=1727000000` (a seconds-era timestamp) is accepted; date is computed as ~1975, wrong. Float `1.5e12` accepted though spec requires 422. | Use `from_ms(raw_ms)` (UTC, integer math). Changed to `is not None` check. Added `_validate_epoch_ms` Pydantic validator that rejects bools, non-integers, and values outside [100_000_000_000, 4_102_444_800_000]. |
| 9 | `punch_in` (lines 104-105) — race condition and status | Check-then-insert: two simultaneous punch-ins for the same employee+date both find no record and both insert, creating duplicates. `body.status` allows any string including `ABSENT`. | 20 concurrent identical punch-ins with `ThreadPoolExecutor` → more than one returns 201. | Unique index on `(emp_code, date)` + catch `DuplicateKeyError → 409`. Pydantic validator restricts `status` to `PRESENCE_STATUSES`. |
| 10 | `punch_in` response (lines 119-121) | Returns an extra `"id"` field (ObjectId string). Datetimes serialised by FastAPI as ISO strings, not epoch ms. | Response contains `"id": "507f1f77bcf86cd799439011"` and `"punch_in": "2026-07-06T03:58:00+00:00"` instead of epoch ms. | Removed `doc["id"]` assignment. Use `to_api_record(doc)` which converts all datetimes to `to_ms()` and strips `_id`. |
| 11 | `GET /attendance` (lines 124-150) | Loads the entire collection into Python with `list(db.attendance_logs.find(q))` and sorts in Python — O(N) memory and a COLLSCAN on 100k records. Sort is by `date` only; spec requires `date DESC, emp_code ASC`. No `date_from > date_to` validation. | On 100k rows the endpoint takes multiple seconds and explain shows COLLSCAN. `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returns 200 instead of 422. | Use cursor `.sort([("date", DESCENDING), ("emp_code", ASCENDING)]).skip(skip).limit(page_size)` with indexes; add `date_from > date_to → 422`; add pagination bounds. |
| 12 | `/health` (lines 72-74) | Always returns `{"status": "ok"}` without pinging MongoDB. If Mongo is down the health check reports healthy; the test runner believes the service is ready and starts sending requests. | Kill MongoDB; `GET /health` still returns HTTP 200. | Added `client.admin.command("ping")` inside `try/except`; returns HTTP 503 on failure. |

## Not defects (checked and left alone)

| Item | Reasoning |
|---|---|
| `load_dotenv()` at module level | `python-dotenv` does not override variables already set in the environment, so real env vars always win. This matches the contract. |
| Synchronous `def` endpoints with PyMongo | FastAPI runs sync handlers in a thread pool executor; blocking Mongo calls are safe and this matches the grader setup. |
